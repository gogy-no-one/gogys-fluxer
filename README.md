# gogys-fluxer-beta

A desktop wrapper for a Fluxer server, built on Electron. It loads the current
web build in a native window instead of pointing a browser tab at a server, and
keeps a separate login for each account you add.

Not affiliated with, endorsed by, or supported by the Fluxer project. Fluxer and
its logo are trademarks of their respective owners. This repository just hosts a
client for a server you already use.

## What it does

- **Always the current web build.** The app shell caches a service worker that
  otherwise pins you to a stale interface. Service worker and cache storage are
  cleared on every launch, so a new deployment shows up immediately.
- **Fullscreen works.** The permission allowlist explicitly includes `fullscreen`,
  which is what makes the fullscreen button in calls work.
- **Separate logins per account.** Every account gets its own storage partition:
  its own cookies, local storage, IndexedDB, service workers and cache. Switching
  between accounts is instant and nothing leaks between them.
- **Several servers at once.** Keep a list of servers, each with its own accounts,
  and switch between them from a window inside the app.
- **Updates itself.** Optionally checks a folder for a newer build, downloads it in
  the background, and installs it when you restart.
- **Sensible defaults.** Screen sharing picks a real screen, notifications and
  clipboard work, links to other sites open in your normal browser instead of
  hijacking the window, and the user agent reports the real Chromium version.

## Install

Grab a file from the [releases page](https://github.com/gogy-no-one/gogys-fluxer/releases).

**Linux** — download the `.AppImage`, then:

```sh
chmod +x gogys-fluxer-beta-2.0.1.AppImage
./gogys-fluxer-beta-2.0.1.AppImage
```

Most Linux desktops can install it from the file manager too. It needs FUSE; on
minimal systems install `libfuse2` first.

**Windows** — download the `-Setup-` `.exe` and run it. The builds are unsigned,
so SmartScreen will warn on first run. Choose *More info → Run anyway*, or build
it yourself.

## First run

The app asks for your server address the first time it starts. Type it in the
form of `chat.example.com` or a full `https://…` URL. There is no pre-filled
server and no baked-in default; whatever you type is what it connects to, which
is the point, because Fluxer servers are self-hosted and yours is not anybody
else's business.

You can also start pointed at a server without touching the saved list:

```sh
./gogys-fluxer-beta FLUXER_URL=https://chat.example.com
```

## Accounts

Click the account button in the bottom right corner of the app window, or press
`Ctrl+Shift+S`, to open **Connections**.

```
● chat.example.com                          [Remove]
    Account 1                        in use  [Open]
    work                                 [Switch to]  [Remove]
    + Add account
+ Add server
```

- **Add account** creates an empty, separate login. The app opens it and you sign
  in like you would on a new device. Nothing from your other account is present.
- **Switch to** makes that account the active one. The window is rebuilt against
  its storage, which takes a moment.
- **Remove** deletes the account *and* wipes the cookies and storage behind it.
  The sign-in is gone for good.
- The green dot marks the server and account currently in use. The button in the
  corner shows the active account name, so you always know which one you are in.

Settings live in `connections.json` in the app's data directory
(`~/.config/gogys-fluxer` on Linux, `%APPDATA%\gogys-fluxer` on Windows). That
file is the whole configuration: delete it to start over, and edit it while the
app is closed to repair a bad entry.

## Updates

The app can update itself, but it has nowhere to fetch from until you tell it.
Open **Connections**, paste a folder URL into the update field, and it will check
that folder for a newer build. If you host your own releases on GitHub, the
folder is:

```
https://github.com/gogy-no-one/gogys-fluxer/releases/latest/download
```

Attach these four files to each release:

| File | Purpose |
| --- | --- |
| `gogys-fluxer-beta-<version>.AppImage` | Linux build |
| `gogys-fluxer-beta-Setup-<version>.exe` | Windows build |
| `latest-linux.yml` | which AppImage is current, with checksum |
| `latest.yml` | which Windows build is current, with checksum |

The two `.yml` files are generated by the build, and they must sit in the same
release as the binaries they describe. Any plain static host works as well —
nothing about the feed is GitHub-specific.

Once an update is downloaded, a **Restart** button appears in Connections and
installs it. `FLUXER_AUTO_UPDATE=0` turns the automatic checks off while leaving
the manual **Check** button working.

Unsigned Windows builds cannot silently replace a signed one, so expect a prompt
there. It works, it just asks.

## Build it yourself

You need Node 20 or newer. `gh` is not required.

```sh
git clone https://github.com/gogy-no-one/gogys-fluxer.git
cd gogys-fluxer-beta
npm install
npm test        # 161 checks, no windows opened
npm run dist    # writes both builds into dist/
```

`npm start` runs the app straight from source, which is the fastest way to try a
change. `npm run build:linux` and `npm run build:win` build one platform at a time.
A full build takes roughly two minutes and needs about 400 MB of disk.

Only the Linux build is possible on Linux; the Windows installer is cross-built
and comes out of the same command.

### Environment variables

| Variable | Effect |
| --- | --- |
| `FLUXER_URL` | Connect to this server on launch instead of the saved one |
| `FLUXER_AUTO_UPDATE=0` | Never check for app updates automatically |
| `FLUXER_APP_UPDATE_CHECK_MS` | How often to check, default 6 hours |
| `FLUXER_AUTO_RELOAD=0` | Never reload when the web build changes |
| `FLUXER_UPDATE_CHECK_MS` | How often to poll for a new web build, default 5 minutes |

## What is in here

| File | Purpose |
| --- | --- |
| `main.js` | Everything: windows, storage, permissions, the server list, updates |
| `web-ui.js` | Preload that draws the account button over the web app |
| `connections-preload.js` | Preload that lets the Connections window talk to the app |
| `test/` | The test suite, run by `npm test` |
| `dist/` | Build output, not tracked by git |

`main.js` is one file on purpose. It is the whole program and it reads top to
bottom.

## Known limits

- The **app icon is the default Electron one.** Nobody has drawn one.
- The Linux and Windows builds are **unsigned**.
- Removing an account wipes its data, but the profile directory itself is left on
  disk rather than deleted.
- Auto-update on Linux only works when the app is run from the AppImage, not from
  a source checkout.
- Nothing is tested on macOS. It may build; nobody has tried.
